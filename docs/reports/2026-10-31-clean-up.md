# Item 1: clean-up check

## Result

The TESS and video probe code is gone, `scripts/check.sh` is green, and the radio path behaves as it did. With no model call, the code rebuilt the request of all 78 of 78 items in the first run, 78 of 78 in the zoom run and 3 of 3 in the recognition check, and each hash equals the one the paid run recorded. The annulus baselines of both runs, redrawn in a temporary folder, are byte-equal to the committed ones in all four files compared (`score.json`, `bar.json`, `records.jsonl`, `score.md`). All of this is in `2026-10-31-clean-up/radio_unchanged.json`.

**Item 4 will not run as planned until a person changes the cap.** `PROBES_CAP_USD` in `probe/harness.py` is still 10 USD and `open_client` takes the lower of it and any `--cap-usd`, so item 4's stop at 36 USD cannot be reached. I left it, since this item allows no behaviour change and the value is a threshold. Item 4 has to raise it and update the tests that pin it.

## What I decided, and why

- **The guard's word lists stay.** `probe/guard.py`, its canaries and its tests still refuse TESS, TIC, TOI and video file names. These are refusals, not references to the removed probes. Narrowing them would change what the radio prompts are checked against and protect nothing. CLAUDE.md also forbids any survey name in a prompt, and this list enforces that.
- **The radio recognition check stays.** It belongs to the radio path, and the first model report relies on it.
- **Dated reports stay as written,** apart from the dead link. `docs/reports/2026-10-31-radio-inputs.md` still says its cost estimate scaled a simulated TESS charge, because that is how the figure was made.
- **`pyvo` stays,** though nothing imports it yet, because item 2 needs it.

## What a reader should doubt

- The check rebuilds requests and baselines. It does not rerun `scripts/radio_inputs.py` against the network, and it makes no model call, so a change in the remote services would not show.
- `astroquery` left the lock with `lightkurve`. Item 5's SIMBAD cross-match must add it, or query SIMBAD another way.
- Some leftovers from the earlier workspace remain because they do not concern these probes: the package name `model-probes` and its description, and the HiRISE and worktree lines in `scripts/run_plan.sh`.
